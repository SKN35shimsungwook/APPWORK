    돈 계산은 정수로02_calculate.py · 05_functions.py

    price = 35000
quantity = 2
discount_percent = 10
subtotal = price * quantity                        # 70000
discount = subtotal * discount_percent // 100      # 7000
print(f"결제 금액: {subtotal - discount:,}원")       # 결제 금액: 63,000원

    왜 실수를 안 쓰나

    컴퓨터는 0.1 + 0.2를 0.30000000000000004로 계산합니다. 돈에 이런 오차가 붙으면 곤란하므로 원 단위 정수로 계산합니다.

    // 와 :,

    //는 몫만 남기는 나눗셈이라 원 미만을 버립니다. f-string의 {값:,}는 천 단위 쉼표를 붙입니다.

    05_functions.py는 같은 계산을 calculate_total(price, quantity, discount_percent=0) 함수로 묶습니다. 할인율 기본값이 0이라 생략할 수 있고, 가격이 음수이거나 수량이 0 이하면 raise ValueError로 멈춥니다.

    products = [
    {"name": "키보드", "stock": 5},

    검색: 리스트 컴프리헨션 + casefold

    term = keyword.strip().casefold()
    return [item for item in PRODUCTS if term in item["name"].casefold()]
    " 무선 "사용자 입력
    → strip() →
    "무선"앞뒤 공백 제거
    → casefold() →
    "무선"대소문자 통일

    주문 함수: 검사 순서가 핵심shop.py의 order()

    order(product_id, quantity, discount_rate="0")는 아래 검사를 위에서 아래로 모두 통과해야만 재고를 깎습니다.

    검사 순서 ↓
    1. 상품 ID 찾기없으면 "존재하지 않는 상품이다."
    2. 수량이 1 이상 정수?아니면 "수량은 1 이상의 정수여야 한다."
    3. 재고 충분?아니면 "재고가 부족하다."
    4. 할인율이 숫자?Decimal 변환 실패 → "할인율은 숫자여야 한다."
    5. 할인율 0~1 사이?아니면 "할인율은 0~1 사이여야 한다."
    6. 재고 차감 + 결과 반환stock -= quantity, {"name", "quantity", "total"}
    통과 시 실행
    순서를 바꾸면 생기는 버그: 재고를 먼저 깎고 할인율을 나중에 검사하면, order(1, 1, "abc")가 오류로 실패했는데 재고는 1개 줄어 있습니다. 테스트 test_invalid_discount_text_preserves_stock이 바로 이 상황을 막습니다.

    Decimal로 할인율 계산

    rate = Decimal(discount_rate)            # "0.10" → 정확한 0.10
discount = int(Decimal(subtotal) * rate)  # 70000 × 0.10 = 7000

    할인율을 문자열 "0.10"으로 받아 Decimal로 바꾸면 실수 오차 없이 계산됩니다. type(quantity) is not int 검사는 True(불리언도 정수 취급됨)나 2.5 같은 값을 걸러냅니다.

    JSON: 파이썬 데이터를 파일로

    path = Path(__file__).resolve().parent / "products.json"
path.write_text(json.dumps(data, ensure_ascii=False, indent=2), encoding="utf-8")
loaded = json.loads(path.read_text(encoding="utf-8"))

    dumps는 객체 → 문자열, loads는 문자열 → 객체. ensure_ascii=False가 없으면 "키보드"가 \ud0a4\ubcf4\ub4dc로 저장됩니다.

    예외: 오류가 나도 멈추지 않게

    for raw in ["3", "abc", "0"]:
    try:
        quantity = int(raw)
        if quantity <= 0:
            raise ValueError("1 이상의 수량을 입력해야 한다.")
        print("수량:", quantity)
    except ValueError as error:
        print("오류:", error)

    "abc"는 int()가, "0"은 직접 만든 raise가 오류를 냅니다. 둘 다 except에서 잡혀 반복이 계속됩니다.

    fixture로 재고 원상복구

    테스트마다deepcopy로 PRODUCTS 사진 찍기→yield: 테스트 실행 (재고 변경)→PRODUCTS[:] = 사진으로 복구
    @pytest.fixture(autouse=True)
def restore_products():
    snapshot = deepcopy(PRODUCTS)
    yield
    PRODUCTS[:] = snapshot

    autouse=True라서 모든 테스트에 자동으로 붙습니다. PRODUCTS = snapshot이 아니라 PRODUCTS[:] = snapshot인 이유는, 다른 파일이 import해 간 같은 리스트 객체의 내용을 바꿔야 하기 때문입니다. =로 새 리스트를 대입하면 다른 파일은 여전히 옛 리스트를 봅니다.

    확인 문제눌러서 답 보기

    list와 dict의 차이는?

    list는 순서가 있는 항목 모음이고([0]으로 접근), dict는 키와 값의 쌍입니다(["name"]으로 접근).

    할인 금액 계산에서 //를 쓰는 이유는?

    원 미만 금액을 버리고 정수 금액을 얻기 위해서입니다.

    함수의 return은 무엇을 하나?

    함수 실행 결과를 호출한 위치로 돌려줍니다.

    JSON 저장 시 ensure_ascii=False의 의미는?

    한글을 ASCII 이스케이프 형태가 아닌 그대로 기록합니다.

    pytest의 fixture가 필요한 이유는?

    테스트 간 공유 재고 데이터 변경을 복원해서 실행 순서에 영향을 받지 않게 하려고 씁니다.

    주문 전에 수량과 할인율을 검사하는 이유는?

    잘못된 주문으로 재고가 차감되는 부작용을 막기 위해서입니다.
