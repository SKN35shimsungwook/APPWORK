PART 1 · 제5장 풀이

Git·GitHub와 Django 쇼핑몰 프로젝트 구축

4장의 정적 HTML을 Django 템플릿으로 옮겨서, 서버가 상품 데이터를 HTML에 채워 보내는 구조를 만듭니다. 코드를 Git으로 기록하고 GitHub에 올리는 법도 배웁니다.

1장2장3장4장5장

4장과 무엇이 달라졌나화면을 누가 만드나

4장 · 브라우저가 만든다

  1. 서버는 빈 index.html을 보냄
  2. 브라우저가 app.js 실행
  3. JavaScript가 상품 카드를 만들어 붙임

페이지 소스를 보면 상품 목록 자리가 비어 있음

5장 · 서버가 만든다

  1. views.py가 상품 목록을 준비
  2. 템플릿에 채워 완성된 HTML을 만듦
  3. 브라우저는 받은 HTML을 그대로 보여 줌

    왜 templates/shop/home.html 처럼 한 번 더 감싸나

    shop\
    ├─ templates\
    │  └─ shop\앱 이름으로 한 번 더
    │     └─ home.htmlrender(..., "shop/home.html")
    └─ static\
       └─ shop\
          └─ style.css{% static 'shop/style.css' %}

    Django는 모든 앱의 templates/를 한데 모아서 찾습니다. 다른 앱에도 home.html이 있으면 이름이 겹칩니다. 그래서 앱 이름 폴더로 한 번 더 구분합니다. static도 같은 이유입니다.

    view와 템플릿shop/views.py · home.html

    PRODUCTS = [
    {"id": 1, "name": "무선 키보드", "price": 35000, "stock": 5},
    {"id": 2, "name": "무선 마우스", "price": 18000, "stock": 8},
    {"id": 3, "name": "모니터", "price": 190000, "stock": 0},
]

def home(request):
    return render(request, "shop/home.html", {"products": PRODUCTS})   # 템플릿에 데이터 전달

def health(request):
    return JsonResponse({"status": "ok", "service": "ai-shop"})       # 서버 상태 확인용

    render(요청, 템플릿, 데이터)가 템플릿에 데이터를 채워 HTML을 만듭니다. 아직 DB 모델을 만들지 않았으므로 2장과 같은 모양의 샘플 목록을 넘깁니다. health는 배포 환경에서 감시 도구가 주기적으로 찔러 보는 주소입니다.

    {% load static %}
<link rel="stylesheet" href="{% static 'shop/style.css' %}">
<a href="{% url 'shop:home' %}">AI Shop</a>

{% for product in products %}
  <article class="card">
    <h3>{{ product.name }}</h3>
    <p class="price">{{ product.price }}원</p>
    <p>{% if product.stock > 0 %}재고 {{ product.stock }}개{% else %}품절{% endif %}</p>
  </article>
{% empty %}
  <p>등록된 상품이 없다.</p>
{% endfor %}

    {{ 값 }}값 출력, 자동 HTML 이스케이프textContent
    {% for %} … {% empty %} … {% endfor %}반복, 목록이 비면 emptyforEach + "검색 결과가 없습니다."
    {% if %} … {% else %} … {% endif %}조건if문

    settings.py: 1장과 다른 점

    1장

    SECRET_KEY = os.environ["DJANGO_SECRET_KEY"]
DEBUG = os.getenv("DJANGO_DEBUG", "False")...

    .env가 없으면 KeyError로 바로 멈춤. DEBUG 기본값 False.

    5장

    SECRET_KEY = os.getenv("DJANGO_SECRET_KEY",
    "insecure-development-only-change-me")
DEBUG = os.getenv("DJANGO_DEBUG", "True")...

    .env가 없어도 개발용 기본 키로 실행. DEBUG 기본값 True. 연습엔 편하지만 운영에선 반드시 진짜 키를 넣어야 함.

    그 밖에 INSTALLED_APPS 끝에 "shop"이 추가됐고, TEMPLATES의 DIRS에 BASE_DIR / "templates"(프로젝트 공통 템플릿 폴더 자리)가 들어갔습니다. .gitignore에는 배포용 staticfiles/도 추가됐습니다.

    확인 문제눌러서 답 보기

    Git과 GitHub의 차이는?

    Git은 로컬 변경 이력 관리 도구이며 GitHub는 원격 저장소·협업 서비스입니다.

    Django의 URL → View → Template 순서는?

    URL이 요청을 View에 연결하고 View가 데이터를 Template에 전달하여 HTML을 반환합니다.

    uv init과 uv venv의 차이는?

    uv init은 프로젝트 기본 설정을 생성하고 uv venv는 가상환경을 생성합니다.

    pytest-django가 필요한 이유는?

    Django 설정과 테스트 클라이언트 등 Django 통합 테스트 기능을 제공하기 때문입니다.

    templates 안에 앱 이름 폴더를 한 번 더 두는 이유는?

    모든 앱의 템플릿이 한곳에서 검색되므로, 다른 앱의 같은 이름 파일과 겹치지 않게 하려는 것입니다.
