HTML·CSS·JavaScript 상품 웹 화면

지금까지는 콘솔에 글자로만 출력했다면, 이번 장은 브라우저 화면을 만듭니다. 파이썬 서버 없이 세 파일로 상품 카탈로그와 장바구니를 만듭니다.

세 파일의 역할뼈대 · 옷 · 근육

assets/app.js근육 · 어떻게 움직이나검색하면 카드 다시 그리기, 담기·삭제·합계
assets/style.css옷 · 어떻게 보이나색, 카드 모양, 3열 → 2열 → 1열 반응형
index.html뼈대 · 무엇이 있나제목, 검색창, 상품 목록 자리, 장바구니 자리
3장과의 관계: 3장은 파이썬이 JSON 파일로 상품을 다뤘고, 4장은 JavaScript가 브라우저 메모리의 배열로 다룹니다. 3장 코드를 복사하지 않는 독립 프로젝트입니다. 5장에서 이 화면을 Django 템플릿으로 옮깁니다.

        1fr은 "남은 공간을 1만큼"이라 repeat(3, 1fr)은 같은 폭 3칸입니다. minmax(0, 1fr)는 긴 상품명이 칸을 밀어내지 않게 최소 폭을 0으로 둡니다. @media는 "화면이 이 폭 이하일 때만" 적용되는 규칙입니다.

        JavaScript: 상태를 바꾸고 화면을 다시 그린다assets/app.js

        사용자 행동
        1. 검색창 입력input 이벤트 → renderProducts(키워드) → 걸러진 카드만 다시 그림
        2. 장바구니 담기 클릭addToCart(id) → cart.set(id, 수량+1) → renderCart()
        3. 삭제 클릭removeFromCart(id) → cart.delete(id) → renderCart()
        4. 전체 비우기cart.clear() → renderCart()
        5. renderCart()목록을 비우고 cart를 처음부터 돌며 줄·합계를 새로 그림
        화면 갱신

        핵심은 "데이터(cart)를 바꾸고 → 화면을 통째로 다시 그린다"입니다. 화면을 조금씩 고치는 대신 매번 새로 그리면 데이터와 화면이 어긋날 일이 없습니다. React 같은 도구도 같은 원리입니다.

        const cart = new Map();                               // 상품ID → 수량
function addToCart(productId) {
  cart.set(productId, (cart.get(productId) || 0) + 1);  // 없으면 0으로 치고 +1
  renderCart();
}
const formatPrice = (price) => `${price.toLocaleString("ko-KR")}원`;   // 79000 → "79,000원"

        왜 Map인가

        상품 ID를 키로 수량을 저장하고 고치기 쉽습니다. set / get / delete / clear / size가 바로 있습니다.

        새로고침하면?

        장바구니가 비워집니다. Map은 브라우저 메모리에만 있고, localStorage 저장은 아직 만들지 않았기 때문입니다.

        textContent vs innerHTML보안 원칙

        위험el.innerHTML = product.name;상품명에 <script>나 <img onerror>가 들어 있으면 그대로 실행됨 (XSS 공격)
        안전el.textContent = product.name;무엇이 들어 있든 글자로만 보여 줌

        app.js는 createElement로 요소를 만들고 textContent로 글자를 넣습니다. 테스트 test_no_unsafe_inner_html이 app.js에 innerHTML이라는 글자가 없는지 검사합니다. 5장의 Django 템플릿 {{ 값 }}도 같은 이유로 자동 이스케이프됩니다.

        4. 접근성

        <label for="search">는 입력란의 의미를 전달하고 클릭으로 포커스를 옮깁니다. aria-live는 바뀐 검색 결과와 장바구니 내용을 보조기술에 알립니다.

        확인 문제눌러서 답 보기

        HTML, CSS, JavaScript의 역할은?

        HTML은 구조, CSS는 디자인, JavaScript는 동작과 상태를 담당합니다.

        defer의 역할은?

        HTML 파싱을 막지 않고 스크립트를 내려받아, 문서 파싱이 끝난 뒤 실행합니다.

        Map을 쓰는 이유는?

        상품 ID를 키로 수량을 저장하고 갱신하기 쉽기 때문입니다.

        textContent를 쓰는 이유는?

        문자열을 HTML로 해석하지 않고 텍스트로 출력하기 때문입니다.

        pytest만으로 브라우저 기능을 검증할 수 있나?

        아닙니다. 이 장의 pytest는 정적 구성을 확인하고, 클릭 동작은 브라우저에서 확인해야 합니다.
