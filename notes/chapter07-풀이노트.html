Docker · MySQL 설치 및 SQL 기초

실무에서 쓰는 MySQL 8.4를 Docker 컨테이너로 띄우고, SQL로 직접 다뤄 본 뒤, Django ORM으로 연결합니다. 6장까지 쓰던 SQLite가 MySQL로 바뀝니다.

Docker가 뭔가프로그램을 "필요한 모든 것과 함께" 상자에 담아 어디서든 똑같이 실행

MySQL을 Windows에 직접 설치

  1. 설치 마법사, 서비스 등록
  2. PC마다 버전·설정이 조금씩 다름
  3. 지울 때 찌꺼기가 남음

Docker로 실행

  1. 설치·설정이 끝난 상자(이미지)를 내려받음
  2. 내 PC든 강사 PC든 서버든 똑같이 동작
  3. 필요 없으면 상자째 버리면 끝

가상머신과 다른 점

가상머신은 운영체제를 통째로 하나 더 띄워 무겁습니다. 컨테이너는 운영체제 핵심(커널)은 같이 쓰고 프로그램만 격리해서 몇 초 만에 켜집니다.

Windows에서는

Docker Desktop이 WSL2라는 작은 리눅스를 깔고, 그 위에서 리눅스 컨테이너(MySQL)를 돌립니다. 그래서 설치할 때 관리자 권한과 재부팅이 필요합니다.

수업에서 Docker를 쓰는 이유: 설치·삭제가 깔끔하고(up -d / down), 수강생 모두 같은 버전·설정을 쓰고, 설정이 compose.yaml 파일 하나에 적혀 Git으로 공유되며, 실무 배포도 대부분 컨테이너로 하기 때문입니다.

    services:
  mysql:
    image: mysql:8.4                                # 어떤 이미지로
    container_name: chapter07-mysql                 # 컨테이너 이름
    restart: unless-stopped                         # 직접 끄지 않으면 자동 재시작
    environment:
      MYSQL_DATABASE: ${MYSQL_DATABASE:?Set MYSQL_DATABASE in .env}
      MYSQL_USER: ${MYSQL_USER:?…}
      MYSQL_PASSWORD: ${MYSQL_PASSWORD:?…}
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD:?…}
    ports:
      - "127.0.0.1:${MYSQL_PORT:-3307}:3306"        # 내 PC에서만, 3307 → 3306
    volumes:
      - mysql_data:/var/lib/mysql                   # 데이터는 볼륨에
      - ./sql:/docker-entrypoint-initdb.d:ro        # 초기화 SQL, 읽기 전용
    healthcheck:                                    # 10초마다 mysqladmin ping
      test: ["CMD-SHELL", "MYSQL_PWD=\"$$MYSQL_PASSWORD\" mysqladmin ping …"]
volumes:
  mysql_data:
    문법뜻
    ${VAR:?메시지}.env에 값이 없으면 메시지를 띄우고 멈춤
    ${VAR:-기본값}값이 없으면 기본값
    127.0.0.1:3307:3306다른 PC에선 접속 불가. 3306 대신 3307을 쓰는 건 PC에 MySQL이 이미 있어도 충돌하지 않게
    $$MYSQL_PASSWORDCompose가 미리 바꾸지 말고 컨테이너 안에서 해석하라는 뜻
    :roread-only. 컨테이너가 sql 폴더를 고치지 못함
    첫 실행에만 적용되는 것: sql/ 초기화 스크립트와 MYSQL_USER·비밀번호 같은 계정 설정은 볼륨이 비어 있을 때 한 번만 적용됩니다. 나중에 .env 비밀번호를 바꿔도 기존 DB에는 반영되지 않아서 "Access denied"가 납니다. 완전히 처음부터 하려면 docker compose down -v(데이터 삭제)를 씁니다.

    사용 순서
    1. docker compose configcompose.yaml + .env를 합친 최종 설정 확인 (오타 검사)

    5. docker compose exec mysql …컨테이너 안에서 명령 실행 (mysql 접속 등)
    6. docker compose down컨테이너 중지·삭제. 볼륨(데이터)은 유지
    7. docker compose down -v볼륨까지 삭제 = 데이터 초기화

    확인 문제눌러서 답 보기

    Docker 볼륨을 사용하는 이유는?

    컨테이너를 종료하거나 다시 생성해도 MySQL 데이터를 유지하기 위해서입니다.

    Django DATABASES의 ENGINE 값은?

    django.db.backends.mysql입니다.

    WHERE, UPDATE, DELETE의 역할은?

    WHERE는 행을 필터링하고 UPDATE는 데이터를 수정하며 DELETE는 행을 삭제합니다.

    SQL 초기화 테이블과 Django Product 테이블의 차이는?

    practice_products는 SQL 연습용이고 shop_product는 Django 마이그레이션으로 생성되는 ORM 테이블입니다.

    pytest-django가 필요한 이유는?

    Django 설정과 테스트 DB, Django 테스트 클라이언트 등 테스트 통합 기능을 제공하기 때문입니다.

    이미지와 컨테이너의 차이는?

    이미지는 실행 준비가 끝난 읽기 전용 틀이고, 컨테이너는 그 이미지로 실제 실행 중인 인스턴스입니다. 이미지 하나로 컨테이너를 여러 개 만들 수 있습니다.
