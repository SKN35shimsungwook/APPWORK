장고는 이렇게 움직인다교재 첫 페이지의 MTV 그림 풀이

장고는 MTV 패턴을 씁니다. 일을 셋으로 나눠서 각 파일이 자기 일만 하게 만드는 방식입니다.

  • Model (models.py): 데이터 모양. "상품에는 이름, 가격, 재고가 있다" 같은 정의.
  • Template (index.html): 화면 모양. 데이터를 끼워 넣을 HTML 틀.
  • View (views.py): 처리 로직. 데이터를 가져와 틀에 채워서 돌려준다.
1장에서는 이 중 일부만 씁니다. config/urls.py 안에 home() 함수를 바로 만들어서 HTML 글자를 돌려줍니다. 템플릿·모델은 다음 장부터 붙습니다.

명령어 풀이교재 2~4장 명령을 단계별로

사전 준비 · 필요한 사람만

교재 2장(VS Code·uv 지우기)은 예전 설치가 꼬였을 때만 하는 초기화입니다. 처음 설치라면 건너뜁니다. Remove-Item -Recurse -Force는 휴지통을 거치지 않고 지우므로, 경로를 꼭 확인하고 실행하세요.

실행 정책 · 한 번만

Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
Get-ExecutionPolicy -List   # CurrentUser 줄이 RemoteSigned면 성공

윈도우는 기본으로 .ps1 스크립트 실행을 막습니다. 가상환경을 켜는 Activate.ps1도 스크립트라서 이 설정을 풀어야 합니다. RemoteSigned는 "내 PC에서 만든 건 허용, 인터넷에서 받은 건 서명 필요"라는 뜻입니다. 한 번 설정하면 계속 유지됩니다.

uv 설치

irm https://astral.sh/uv/install.ps1 | iex
uv --version

irm이 설치 스크립트를 내려받고, |(파이프)가 그 결과를 넘기면, iex가 실행합니다. "내려받아서 바로 실행"을 한 줄로 한 것입니다.

프로젝트 만들기

uv python install 3.12                    # uv가 관리하는 파이썬 3.12 설치
uv init chapter01_project --python 3.12  # 폴더 + pyproject.toml + .python-version + main.py
cd .\chapter01_project

가상환경

uv venv                         # .python-version(3.12)을 보고 .venv 생성
.venv\Scripts\activate          # 프롬프트 앞에 (.venv)가 붙으면 성공
python -c "import sys; print(sys.executable)"  # ...\.venv\Scripts\python.exe 가 나와야 함

교재 본문은 uv venv만 쓰라고 하고, 결과 예시에는 uv venv .venv --python 3.12가 나옵니다. 둘 다 결과가 같습니다. .venv는 기본 폴더 이름이고, 3.12는 이미 .python-version에 적혀 있기 때문입니다.

패키지 설치

uv add "django==5.2.7" "python-dotenv==1.1.1"
uv tree                         # 무엇이 무엇을 끌고 들어왔는지 나무 모양으로
uv lock --check                 # uv.lock이 최신인지 확인
uv add --dev "pytest>=8,<10" "pytest-django>=4.8,<5"   # 테스트용(개발 전용) 패키지

==는 "정확히 이 버전", >=8,<10은 "8 이상 10 미만"입니다. --dev를 붙이면 실제 서비스에는 필요 없고 개발할 때만 쓰는 패키지로 따로 분류됩니다.

장고 뼈대 만들기 · 다음 차례

uv run django-admin startproject config .
if (Test-Path .\main.py) { Remove-Item .\main.py }   # uv init이 만든 main.py는 장고에서 안 씀

config는 설정 폴더 이름이고, 끝의 점(.)이 중요합니다. "지금 폴더에 바로 만들어라"는 뜻입니다. 점을 빼면 config\config\처럼 폴더가 한 겹 더 생겨서 교재 구조와 달라집니다.

uv run은 "이 프로젝트의 가상환경으로 실행해라"입니다. 가상환경을 켜 둔 상태라면 django-admin ...만 쳐도 되지만, uv run을 붙이면 켜져 있든 아니든 항상 맞는 환경에서 돌아갑니다.

교재 5장은 완성된 프로젝트에 들어 있는 파일을 하나씩 설명합니다. 각 파일이 언제 생기는지와 무슨 일을 하는지를 같이 보면 순서가 잡힙니다.

    settings.py 뜯어보기장고 설정의 본체

    BASE_DIR · 프로젝트 루트 찾기

    BASE_DIR = Path(__file__).resolve().parent.parent

    "settings.py가 있는 곳에서 두 칸 위로 올라가면 프로젝트 맨 위 폴더"라는 계산입니다. 이렇게 해 두면 프로젝트를 다른 PC나 다른 폴더로 옮겨도 경로가 자동으로 맞춰집니다.

    chapter01_project\.parent.parent = BASE_DIR
    ├─ manage.py
    ├─ .env
    └─ config\.parent
       ├─ settings.py__file__ (나 자신)
       └─ urls.py

    그다음 BASE_DIR / ".env", BASE_DIR / "db.sqlite3"처럼 씁니다. 여기서 /는 나눗셈이 아니라 경로를 이어 붙이는 기호입니다.

    • DEBUG: 개발 중엔 True(에러 화면 자세히), 실제 서비스에선 False. 문자열 "True"를 소문자로 바꿔 "true"와 비교해서 참·거짓을 만듭니다.

    MIDDLEWARE · 요청이 지나가는 검문소

    모든 요청은 view에 닿기 전에 미들웨어를 위에서 아래로 통과하고, 응답은 아래에서 위로 거꾸로 통과합니다. 그래서 순서가 중요합니다. 예를 들어 4번(로그인 사용자 확인)은 2번(세션)이 먼저 있어야 동작합니다.

    요청 들어옴 ↓
    1. SecurityMiddleware보안 헤더, HTTPS 강제
    2. SessionMiddlewarerequest.session 사용 가능 → 장바구니
    3. CommonMiddleware주소 끝 / 정리
    4. CsrfViewMiddleware위조 요청 차단 → 폼에 {% csrf_token %}
    5. AuthenticationMiddlewarerequest.user 사용 가능 → 로그인 확인
    6. MessageMiddleware일회성 알림 전달
    7. XFrameOptionsMiddleware다른 사이트의 iframe 삽입 차단
    8. View 실행views.py의 함수가 응답을 만든다
    응답 나감 ↑
    중간 검문소가 요청을 먼저 막고 바로 응답할 수도 있습니다. 예를 들어 CSRF 토큰이 없는 POST 요청은 View까지 가지 못하고 403 에러로 돌아갑니다.

    확인 문제눌러서 답 보기

    uv add와 uv sync의 차이는?

    uv add는 새 패키지를 목록(pyproject.toml)에 추가하고 설치합니다. uv sync는 이미 적힌 목록·잠금 파일에 맞춰 .venv를 맞춥니다.

    uv.lock은 왜 있나?

    장고가 끌고 오는 하위 패키지(asgiref, sqlparse 등)까지 정확한 버전을 기록합니다. 다른 사람 PC에서도 똑같은 환경을 재현할 수 있습니다.

    .env와 .env.example의 차이는?

    .env는 진짜 비밀값이라 Git에서 제외합니다. .env.example은 "이런 이름의 값이 필요하다"는 견본이라 공유합니다.

    Set-Location과 cd의 관계는?

    같은 명령입니다. PowerShell에서 cd는 Set-Location의 별칭입니다. ls·dir도 Get-ChildItem의 별칭입니다.

    SECRET_KEY를 코드에 직접 쓰지 않는 이유는?

    코드는 GitHub 등에 공유되므로 유출 위험이 있고, 개발·운영 환경마다 다른 키를 쓰기 위해 설정을 코드에서 분리합니다.

    startproject config .에서 마지막 점을 빼면?

    config\ 폴더 안에 다시 manage.py와 config\가 생겨 한 겹 더 깊어집니다. 교재의 경로·명령이 전부 어긋납니다.
