왜 나누나

나중에 JSON 파일을 MySQL로 바꿀 때 repository.py만 고치면 됩니다. 주문 규칙(service)이나 명령어(cli)는 그대로 둡니다. 7장에서 실제로 이렇게 바꿉니다.

각자 아는 것만

cli는 화면 출력만, service는 규칙만, repository는 파일만 압니다. service는 "JSON인지 DB인지" 모릅니다. 이렇게 모르는 게 많을수록 바꾸기 쉽습니다.

파일 탐색기파일 이름을 누르면 설명이 나옵니다

    사용자 정의 예외catalog/exceptions.py

    class ProductError(Exception):
    """상품 처리 실패를 표현하는 기본 예외."""

class ProductNotFoundError(ProductError):
    """상품 ID가 존재하지 않을 때 발생한다."""

class InsufficientStockError(ProductError):
    """요청한 주문 수량이 재고를 초과할 때 발생한다."""
    Exception파이썬 기본 예외모든 예외의 조상
    ProductError상품 처리 실패 (부모)이걸 잡으면 아래 둘이 한꺼번에 잡힘
    ProductNotFoundError상품 없음order(999, 1)
    InsufficientStockError재고 부족order(3, 1) · 모니터 재고 0

    ValueError 하나로 다 처리하면 "상품이 없는 건지 재고가 없는 건지"를 메시지 글자로만 구분해야 합니다. 이름을 붙이면 except ProductNotFoundError:처럼 종류별로 다르게 처리할 수 있고, 테스트도 pytest.raises(InsufficientStockError)처럼 정확히 검사할 수 있습니다.

    repository · 창고 관리인catalog/repository.py

    def load(self) -> list[dict]:
    if not self.path.exists():
        return [product.copy() for product in DEFAULT_PRODUCTS]   # 첫 실행: 기본 상품
    with self.path.open("r", encoding="utf-8") as file:
        data = json.load(file)
    if not isinstance(data, list):
        raise ValueError("상품 데이터는 리스트여야 합니다.")
    return data

def save(self, products: list[dict]) -> None:
    self.path.parent.mkdir(parents=True, exist_ok=True)               # data/ 폴더 자동 생성
    with self.path.open("w", encoding="utf-8") as file:
        json.dump(products, file, ensure_ascii=False, indent=2)
    • 파일이 없으면 기본 상품 3개를 복사해서 돌려줍니다. .copy()를 하는 이유는 원본 DEFAULT_PRODUCTS가 주문으로 바뀌지 않게 하려는 것입니다.
    • 파일 내용이 리스트가 아니면 ValueError, JSON 문법이 깨졌으면 json.JSONDecodeError가 납니다. 테스트 두 개가 이걸 확인합니다.
    • with ... as file:은 블록이 끝나면 파일을 자동으로 닫아 줍니다.
    • mkdir(parents=True, exist_ok=True): 상위 폴더까지 만들고, 이미 있어도 오류를 내지 않습니다.

    service · 주방장catalog/service.py

    class ProductService:
    def __init__(self, repository: ProductRepository):
        self.repository = repository                  # 저장소를 밖에서 받는다

    def order(self, product_id: int, quantity: int) -> dict:
        if quantity <= 0:
            raise ValueError("주문 수량은 1 이상이어야 합니다.")
        products = self.repository.load()
        product = next((p for p in products if p["id"] == product_id), None)
        if product is None:
            raise ProductNotFoundError(f"상품 {product_id}번이 없습니다.")
        if product["stock"] < quantity:
            raise InsufficientStockError("재고가 부족합니다.")
        product["stock"] -= quantity
        self.repository.save(products)
        return {"name": ..., "quantity": ..., "total": product["price"] * quantity, "stock": ...}
    의존성 주입: service가 저장소를 직접 만들지 않고 생성자로 받습니다. 그래서 실제 실행에서는 data/products.json 저장소를, 테스트에서는 임시 폴더 저장소를 끼워 넣을 수 있습니다. 같은 service 코드가 두 환경에서 그대로 돌아갑니다.

    next((... for ...), None)은 "조건에 맞는 첫 번째 것, 없으면 None"을 한 줄로 찾는 방법입니다. 2장과 마찬가지로 검사를 모두 통과한 뒤에 재고를 줄이고 저장합니다.

    예상 가능한 오류(ProductError, ValueError, OSError)는 오류: …로 출력하고 종료 코드 1을 돌려줍니다. 성공은 0입니다. main.py의 raise SystemExit(main())가 이 숫자를 운영체제에 넘깁니다. 다른 프로그램이나 스크립트는 이 숫자로 성공·실패를 판단합니다.

    모듈과 패키지의 차이는?

    모듈은 .py 파일 하나, 패키지는 관련 모듈을 묶은 폴더 구조입니다.

    if __name__ == "__main__":의 목적은?

    직접 실행할 때만 진입점 코드를 실행하고, import할 때는 실행되지 않게 합니다.

    JSON 저장에서 ensure_ascii=False의 역할은?

    한글을 유니코드 이스케이프가 아닌 읽기 쉬운 문자로 기록합니다.

    사용자 정의 예외가 필요한 이유는?

    상품 없음·재고 부족 같은 업무 실패를 명확하게 구분해 처리하기 위해서입니다.

    pytest의 tmp_path fixture를 쓰는 이유는?

    테스트별 임시 파일을 써서 실제 data/products.json을 바꾸지 않기 위해서입니다.

    conftest.py는 어떻게 실행하나?

    직접 실행하지 않습니다. uv run pytest -v를 하면 pytest가 자동으로 불러옵니다.
